# 受控作业与逐机证据

本轮实现 F03、F05 以及 F04 的首批验证、人工放行、失败停止。入口为「作业库」。原有批量命令、命令模板、脚本库和历史任务仍可使用；作业库可把旧内容复制为独立草稿。

## 第一次使用

1. 管理员进入作业库，选择「新建作业」。初始表单是一条仅限测试环境的系统信息查询；可直接保存为草稿。这里不会连接主机。
2. 配置用途、参数、环境、允许主机、SSH 账号或 CMDB 系统名称限制。命令模板用独立的 `{{参数名}}` 占位符；Shell/Python 参数按表单顺序作为独立位置参数传递。
3. 保存后发布。修改已发布内容会产生新草稿，重新发布后才可新提交。维护抽屉能查看版本、操作者、时间，也可复制历史内容作为新的草稿。
4. 运行者填写参数，按先后选择目标。前 N 台是首批。确认前查看具体目标、版本、参数、脚本快照和验证方式。预览有效期 10 分钟，不连接目标，也不模拟任意脚本的副作用。
5. 普通用户提交后等待审批。生产或修改类作业必须填写原因、配置 systemd 服务验证，并由另一位管理员审批。只有一位管理员时，受控变更会停在待审批。
6. 首批全通过且还有目标时，任务进入「待首批放行」，不占用执行器。打开任务详情核对逐机结果，再手动放行；受控变更须由另一位管理员放行。
7. 后续按批次和并发上限执行，累计失败数达到阈值时不再派发。同一执行波已经派发的主机可能完成。失败与取消均不等同于自动回滚。

## 状态与审计

- 确认计划绑定用户、发布版本、脚本、参数和有序目标；目标连接地址、端口、账号或环境等变化需要重新提交。审批、放行和派发会重新检查权限及目标快照。
- 每台主机记录批次、排队、SSH、投递、预检、执行、清理及可选服务验证。阶段保存耗时和脱敏摘要；输出采用有上限的预览。清理状态表示已尝试，不表示远端所有文件均被删除。
- 失败原因可筛选；区分尚未执行、脚本已尝试派发与远端状态待核查。执行器丢失租约后不会自动重放。非成功主机可单独重试；可能已执行时需先核实远端，再显式确认。
- 受控作业 CSV 增加批次、失败分类、派发状态、退出码和阶段。旧任务的 CSV 结构保持不变。
- 已提交任务使用原快照；编辑或停用定义只影响新提交。重试使用原版本和参数，生成新的审批及批次记录。

## 当前边界

「只读」是维护者审核的用途分类，Shell/Python 不是沙箱。当前服务验证是 `systemctl is-active`，只能确认该服务单元状态，不替代 HTTP 业务验证。平台不会自动安装解释器，也不会保证取消时远端子进程已经终止。自定义回退、维护窗口、细粒度 RBAC、分环境凭据与正式生产部署不是本轮内容；旧临时执行仍沿用原权限策略。

## 验证

- 后端测试涵盖版本与计划防篡改、目标授权、首批失败停派、人工放行、失败阈值、审批分离、资产变化、重试核查、租约恢复和服务验证失败。
- `scripts/smoke-managed.py` 使用本地 SQLite、临时用户和环回资产，验证浏览器中的草稿、发布、参数与目标预览、提交待审批、阶段和放行确认界面。放行样本是隔离数据，浏览器检查不会批准或放行任何作业。
