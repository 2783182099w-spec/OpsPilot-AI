
# 告警诊断策略实施计划

目标是让操作者查阅诊断目录，并把告警来源、资产范围、诊断树版本、结论和人工或自动处理方式关联起来。

1. 在 `mtask/diagnostics.py` 和 `diagnostic_routes.py` 沿用已有诊断及证据解析。新增诊断目录，区分内置检查和自建树。
2. 在 `mtask/models.py`、迁移和 `diagnostic_workflows.py` 保存策略与执行记录。接入现有任务执行器，按告警轮次去重。告警触发与定时扫查调用同一流程，定时扫查针对仍活跃的告警。
3. 复用 Nginx 固定恢复脚本和独立审批。仅允许已绑定的 HTTP 探测及指定树结论申请修复。全局开关、测试环境、维护、授权、并发和冷却保护继续生效。执行后同时查看本机验证与外部探测结果。
4. 在诊断策略和告警详情显示证据、分支、待审批、复检及转人工。验证权限、重复触发、条件变化、失败和恢复，完成迁移检查与本地前端构建。

上线前备份本地数据库，核对在途任务。停用策略可停止新诊断并使尚未派发的修复失效。迁移为增量表结构，保留历史告警和任务。本地验证以隔离样本和模拟结果为准。

## 本地使用

1. 在侧栏「诊断与修复」查看内置目录、自建配置、联动和诊断结果。自建树支持从 Nginx 示例新建、保存版本和在指定资产上只读试跑。
2. 在「告警联动」选择来源和资产。可选按来源匹配内置检查、使用内置 Nginx 树或锁定一版自建树。新建策略默认停用。
3. 按需选择只读、审批后修复或自动修复。Nginx 修复需绑定一个已启用恢复的 HTTP 探测和一个确定的结论。SSH 基线可选按来源匹配的固定诊断和独立审批。通往该结论的每条路径都须确认同一 HTTP 端点异常、Nginx 未运行，且无待确认的节点。
4. 选择随告警触发或定时扫描。定时扫描针对活跃告警，间隔为 15 到 1440 分钟。启用定时的只读策略可复查同一轮仍活跃的告警。修复每轮最多提交一次。多条策略同时命中会要求人工核对。
5. 在「告警中心 → 告警详情 → 排查与恢复」点击「一键诊断」。符合修复条件后，可在同一区域发起本次修复授权；审批型策略命中时会直接生成待审批记录。另一名管理员可从该告警详情或告警中心的「待审批」核对并放行。诊断策略用于修复的证据有效期为 15 分钟，单台主机修复冷却期为 30 分钟。
6. Nginx 本机复检通过后，仍须外部 HTTP 探测确认恢复。两分钟内未确认、动作失败或证据不足时，若启用了转人工，告警会进入站内待人工队列。转人工使用告警中心的接手机制。

已有探测的旧入口继续处理未受新策略管控的告警。审批或自动策略管控的告警通过绑定结论进入修复流程。只读策略诊断完成后，符合条件的 Nginx 告警仍可独立发起一次修复审批。停用或修改策略会使旧版本尚未派发的修复失效。

## 受控 SSH 基线修复与入口合并

目标是在告警中完成本轮诊断、发起审批、执行与复检，把模板、联动和结果集中在「诊断与修复」。待审批并入告警中心，旧链接保留跳转。

- 在现有诊断和任务模块增加固定的 SSH 密码认证与 root 密码认证修复。只接收测试资产上同轮、近期、有确切异常证据的专项诊断结果，复用独立管理员审批、资产快照和 SSH 指纹。执行前再次核对。
- 限定 root 密钥可登录且使用标准配置路径和服务单元的主机。先检查配置和回滚能力，再改文件并重载；用新的密钥连接完成复检。超时或连接失败触发主机侧定时回滚。遇到复杂 SSH 配置转人工。
- 在 Vue 中合并诊断树、联动与结果。告警根据实际能力显示审批、人工处理或复检；待审批列表沿用现有接口。
- 先用隔离样本验证权限、证据、脚本预检、密钥复连失败和回滚，再运行后端回归及前端构建。此次无数据库结构变更。恢复路径是停用相关入口并保留既有任务记录；SSH 变更的主机端回滚与任务证据单独记录。

### SSH 基线处理范围

- 「SSH 密码登录策略」会申请将 `PasswordAuthentication` 和 `KbdInteractiveAuthentication` 设为 `no`。执行前重新核对当前策略仍与证据一致。
- 「SSH root 登录策略」会申请将 `PermitRootLogin` 设为 `prohibit-password`，禁用 root 的密码和键盘交互认证并保留密钥通道。[OpenSSH sshd_config 手册](https://man.openbsd.org/sshd_config#PermitRootLogin)
- SSH 修复仅在测试资产使用，须已有可信指纹和可用的 root 密钥。检查失败、非标准启动参数、`Match` 条件或非标准 Include 转人工。审批和派发时复核告警轮次与 15 分钟证据。未经派发的过期申请取消后，可以重新诊断再提交。
- 主机先把配置备份保存到 root 专用目录，并确认 systemd 临时回滚计时器已生效。重载后，平台以全新的密钥会话复检并确认提交。失联时由主机回退，遇到配置被外部改动会保留备份并要求人工核对。计时器覆盖进程中断和连接丢失场景，主机重启期间须使用控制台核对备份。[systemd-run 手册](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)
