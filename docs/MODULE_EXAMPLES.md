# OpsPilot-AI 模块示例

部署后使用管理员登录。页面里以「示例 ·」标记的数据用于演示。示例资产 `192.0.2.10` 是保留地址，复制示例后替换为已授权的测试资产。

| 模块 | 示例 | 在哪里查看或配置 |
| --- | --- | --- |
| 登录与用户管理 | 新建运维员 `example-operator`，只授权一台测试资产。观察员用于只读验收。审批演练使用另一位管理员。 | 用户管理 |
| 运维总览 | 核对资产、告警和任务卡片，打开示例 CPU 巡检任务。 | 运维总览 |
| CMDB | Linux Web 节点，分组「测试资产」，环境「测试」，维护状态「维护中」。 | 资产管理、主机工作台 |
| Web SSH | 在授权测试资产登记可信 SSH 指纹并确认平台公钥已授权，连接后运行 `id` 和 `uptime`。 | 资产管理 → Web SSH |
| 批量作业 | 用「查看系统负载」模板选择两台测试资产，分别核对退出码和执行输出。 | 作业库、批量作业 |
| Shell / Python | Shell 采集 `df -hP`，Python 返回内核版本和磁盘容量。 | 作业库 → 脚本 |
| 受控作业 | 「首批检查系统负载」草案，测试环境、首批 1 台、允许资产明确列出。 | 作业库 → 受控作业 |
| 健康巡检 | CPU、内存、磁盘、负载。查看带「示例」标记的模拟结果，或在已授权主机上重新巡检。 | 健康巡检、任务中心 |
| 定时巡检 | 每 60 分钟运行健康巡检，绑定测试资产。内置示例处于停用状态。 | 健康巡检 → 定时检查 |
| 监控 | Node Exporter 采集地址示例 `192.0.2.10:9100`，CPU 持续高于 90% 触发告警。 | 监控中心 |
| HTTP 服务探测 | Web 节点端口 80，路径 `/`，连续失败后生成服务告警。示例探测处于停用状态。 | 诊断与修复 → 告警联动 → 服务探测 |
| 告警与接手 | 「示例 · HTTP 503 排查」含模拟证据，用于查看告警详情、填写负责人和处理记录。 | 告警中心 |
| 诊断树 | HTTP 失败 → 查 `nginx.service` → 检查近期日志或得出服务未运行结论。自建示例可复制并试跑。 | 诊断与修复 → 自建诊断树 |
| 审批与复检 | Nginx 持续异常且诊断命中「服务未运行」后，生成修复审批。SSH 示例适用于具备可信指纹和 root 密钥的测试资产。 | 告警中心 → 待审批 |
| 定时诊断 | 监控指标 `cpu`，按来源选择专项检查，每 30 分钟复查活跃告警，处理方式选只读。 | 诊断与修复 → 告警联动 |
| 发布流水线 | `example-web` 应用草案，绑定测试资产、`example-web.service`、可信 HTTPS 制品源、端口 8080 和 `/health`。 | 发布流水线 → 发布应用、发布指引 |
| 任务审计 | 打开模拟巡检任务，检查执行人、状态、单机结果和可导出的报告。Web SSH 会话在同一模块另有页签。 | 任务中心 |
| AI 助手 | 在「日志分析」粘贴下方模拟日志。使用部署侧模型密钥或通过页面配置个人密钥。 | AI 助手 |

## AI 日志分析输入

```text
2026-01-01T10:10:03Z nginx  upstream connect() failed (111: Connection refused)
2026-01-01T10:10:03Z access GET /health HTTP/1.1 503 upstream=127.0.0.1:8080
2026-01-01T10:10:08Z example-web.service stopped after exit-code=1
请指出已确认的事实、可能原因、建议的只读检查，以及恢复后的验证办法。
```

## CI 上报参数示例

在应用详情生成 CI Token 后，保存为 CI 密钥。将下方值替换为自己的 HTTPS 制品源和制品真实 SHA-256，再使用发布指引中的 CI 命令模板。

```json
{
  "version": "1.0.0",
  "url": "https://artifacts.example.com/example-web/1.0.0/app.tar.gz",
  "sha256": "由流水线针对该制品实际计算的 64 位十六进制 SHA-256"
}
```
